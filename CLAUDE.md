# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this project is
Path of Building Community (PoBC) is an offline build planner for Path of Exile. It runs on a custom C++-backed runtime (`SimpleGraphic`) and is written almost entirely in **LuaJIT 5.1**. The executable (`runtime/Path of Building.exe`) loads `src/Launch.lua`, which bootstraps the rest of the application.

## Running the program
```
runtime/Path of Building.exe
```
Dev mode is auto-detected when `manifest.xml` is missing a `branch`/`platform` attribute.

Dev-mode keybindings:
- `F5` — hot-reload
- `Ctrl+~` — toggle in-app console
- `Ctrl+F5` — full restart + regenerate `src/Data/ModCache.lua`
- Hold `Alt` — extended tooltip debugging
- Hold `Ctrl` at launch — force-rebuild ModCache

## Running tests
```bash
docker-compose up
# or locally (if Busted + LuaJIT installed):
cd src && busted --lua=luajit
# single spec:
cd src && busted --lua=luajit ../spec/System/TestDefence_spec.lua
```

## ModCache regeneration
After changing `src/Modules/ModParser.lua` or anything affecting mod parsing, regenerate and commit `src/Data/ModCache.lua` — CI will fail otherwise:
```bash
cd src && REGENERATE_MOD_CACHE=1 luajit HeadlessWrapper.lua
# or: docker-compose run busted-tests sh -c "cd src && REGENERATE_MOD_CACHE=1 luajit HeadlessWrapper.lua"
```

## Architecture

### Entry & modes
`src/Launch.lua` → `Modules/Main.lua` owns two modes:
- `"LIST"` → `Modules/BuildList.lua` (build selection screen)
- `"BUILD"` → `Modules/Build.lua` (active build editor, owns all UI tabs)

No standard `require`; modules use `PLoadModule`/`LoadModule` (wrappers around `loadfile`) and share a global environment.

### Calculation pipeline (`Modules/Calc*.lua`)
| File | Responsibility |
|---|---|
| `CalcSetup.lua` | Builds mod databases; processes nodes, jewels, flasks, items, skills |
| `CalcPerform.lua` | Top-level orchestrator |
| `CalcOffence.lua` | DPS, hit chance, damage types, ailments |
| `CalcDefence.lua` | Life, ES, armour, resistances, mitigation |
| `CalcTriggers.lua` | Trigger-based skill interactions |
| `CalcActiveSkill.lua` | Per-skill output table |
| `CalcSections.lua` | Calcs-tab display sections |
| `CalcTools.lua` | Shared helpers: mod summing, gem validation |

Results: `env.player.output` / `env.enemy.output`. Breakdown tables for the Calcs tab: `env.player.breakdown`.

### Mod system
```lua
mod(ModName, ModType, Value, source, modFlags, keywordFlags, ...extraTags)
```
- **ModType**: `"BASE"`, `"INC"`, `"MORE"`, `"FLAG"`, `"OVERRIDE"`, `"MAX"`, `"MIN"`
- **ModFlags/KeywordFlags**: bitfield enums in `src/Data/Global.lua`
- **ExtraTags**: `{ type = "Condition", var = "..." }`, `{ type = "Multiplier", var = "..." }`, etc. — see `docs/modSyntax.md`
- All mod text is lowercased before parsing — write `ModParser.lua` patterns in lowercase
- Storage/query: `Classes/ModDB.lua`, `Classes/ModList.lua`, `Classes/ModStore.lua`

### Data layer
`Modules/Data.lua` loads all game data from `src/Data/`. Files with `-- This file is automatically generated` headers must **not** be hand-edited — change `src/Export/Scripts/` instead and re-run the exporter. `src/Data/Global.lua` holds all enum tables.

### UI layer
All controls inherit from `Classes/Control.lua` via `new()` factory in `Modules/Common.lua`. Tab classes are in `src/Classes/`. Class system:
```lua
newClass("MyClass", "BaseClass", function(self, ...) end)
local obj = new("MyClass", ...)
```

## Key conventions
- **Lua version**: LuaJIT 5.1. Use `bit.bor`/`bit.band` for bitwise ops (no `~` or `&`). String patterns use Lua syntax, not PCRE.
- **PRs target `dev`**, not `master`. `master` is release-only.
- **ModCache must be committed** whenever `ModParser.lua` changes.
- **Auto-generated files** in `src/Data/` must not be edited directly.
